# 個人のリソース（利用者ごとのデータ）

血液検査の結果のように、利用者本人だけのデータを情報源として登録し、健康寿命などのジャンルで、共有の知識（動画・Web ページから作った概念）と結びつけて分析する。

## 方針

- **本人だけが見られる。** 個人のファイルと、そこから作った分析・概念・関係・出典は、持ち主だけが見られる。他の利用者からは一覧にも件数にも出ず、URL を開いても 404 になる。
- **共有の知識とは、本人の画面でだけつながる。** 分析で共有の概念（例「アルブミン値と栄養状態」）と同じ意味の概念が出たら、その共有の概念を再利用する。つないだ関係と出典は本人だけのものなので、他の利用者が同じ概念を開いても、本人のデータは見えない。
- **テーブルは分けない。** `videos.source_type = file` として情報源に登録し、分析の版・ジョブ・知識の候補づくりをそのまま使う。見える範囲は `owner_id` で分ける（knowledge_tables.md の「owner_id」）。
- **AI（Gemini）に送るのは、データの表と既存の概念の名称だけ。** 利用者の名前など本人を特定する情報は送らない。既存の概念は、共有の概念と本人の概念だけを渡す。
- **診断はしない。** 基準値を外れた項目を挙げ、共有の知識と結びつけるところまで。受診・相談につなげる書き方にする（`PersonalDataAnalyst` の指示）。

## 登録（`RegisterPersonalFile`）

情報源一覧の「個人のファイル」から CSV をアップロードする。ジャンルの初期値は「健康寿命」。

| 項目 | 内容 |
|---|---|
| 形式 | CSV（1 行目が見出し）。UTF-8（BOM 付きも可）か Shift_JIS。1 MB まで |
| 保存先 | `storage/app/private/resources/{利用者 ID}/{中身の SHA-256}.csv`（公開されない local ディスク）。`public/` には置かない |
| 二重登録 | 同じ利用者が同じ中身のファイルを上げたら、登録済みのものを開く |
| videos | `source_type = file`、`title` はファイル名、`owner_id`・`registered_by` は本人、`url` は空 |

## 分析（`GeminiPersonalFileAnalyzer`・`PersonalDataAnalyst`）

1. CSV を「列 | 列 | …」の表にする（`PersonalFileReader`）。値のない行（「乳ビ,,,」など）は除く。
2. 表と、既存の概念（同じジャンルの概念を先に）を渡して分析する。
3. 要点には、根拠となる表の行をそのまま引用させる。表に見つからない引用は空にする（Web ページと同じ）。
4. 表は `video_analyses.source_text` に分析の版ごとに残す（`source_url` は空）。詳細画面の「分析に使ったデータ」で確認できる。

概念の扱い：

| AI が返した概念 | 登録のしかた |
|---|---|
| 共有の概念と同名 | 共有の概念を再利用する（概念は共有のまま）。関係と出典は本人だけ |
| 本人の概念と同名 | 本人の概念を再利用する |
| 新しい名称 | 本人だけの概念として作る |

共有の情報源（YouTube・Web ページ）の分析は、共有の概念だけを再利用する。他の利用者の個人の概念は、プロンプトにも渡さず、同名でもつながない。

## 知識の操作の規則（`KnowledgeCurator`）

| 操作 | 規則 |
|---|---|
| 統合 | 個人のノードを共有のノードに統合できる（付け替えた関係・出典は本人だけのまま）。共有のノードを個人のノードには統合できない |
| 関係の追加 | 持ち主の違う個人のノードどうしはつなげない |
| 設計判断・実装を作る | 個人の概念から作ったものは本人だけのものにする（名称から本人の状態が分かることがあるため） |
| 制作 | 制作は全員で共有するので、個人の設計判断からは作れない |

## 見える範囲の仕組み

- `VisibleToCurrentUser`（全体にかけるスコープ）：ログイン中の利用者には、`owner_id` が空か自分のものだけを返す。画面の一覧・件数・関連の読み込み・URL からの読み込みのすべてに効く。
- キューのジョブとコマンドはログインしていないので、このスコープはかからない。分析では `visibleTo(持ち主)` で明示的に絞る。
- 知識入りの graph.html（`bin/knowledge-graph`）はファイルとして共有されるので、共有のノード・関係だけを書き出す。
- 統合・循環の判定は、他の利用者の個人の関係も含めて行う（付け替え漏れや、見えない循環を防ぐため）。

## まだ対応していないもの

- 本人が選んだ人（家族・医師など）との共有
- PDF・画像の検査結果（CSV だけ）
- 検査結果の時系列の比較（複数回の結果を並べる）
- `php artisan knowledge:embed --duplicates` は管理用のコマンドなので、個人の概念も表示する
